4️⃣ Transaction Manager (ACID)
Transactions ensure database reliability.

ACID =

A — Atomicity
All or nothing.

C — Consistency
Database remains valid.

I — Isolation
Transactions don’t see each other’s mess.

D — Durability
Once committed → permanent.

Example:

BEGIN
UPDATE accounts SET balance = balance - 500
UPDATE accounts SET balance = balance + 500
COMMIT
If crash happens mid-way → rollback.

5️⃣ WAL (Write Ahead Logging)
Very important.

Used by:

PostgreSQL

MySQL

Principle:
Write changes to log FIRST
Then modify actual data file

Why?

If crash happens:

Read log

Replay committed transactions

Undo incomplete ones

WAL Flow:
User Update
   ↓
Write log entry
   ↓
Flush log to disk
   ↓
Modify actual page
Without WAL → database corruption risk.

🔹 Page Header Structure (64 Bytes)
struct PageHeader {
    uint32_t page_id;            // 4 bytes
    uint32_t table_id;           // 4 bytes
    uint16_t free_space_offset;  // 2 bytes
    uint16_t slot_count;         // 2 bytes
    uint32_t lsn;                // 4 bytes (Log Sequence Number)
    uint8_t  page_type;          // 1 byte (data/index)
    uint8_t  reserved[47];       // padding to 64 bytes
};

struct SlotEntry {

};

Records grow upward.

4️⃣ Concurrency Control Design
Two options:

🔒 Option 1: Lock-Based (2PL)
Used by older engines.

Two Phase Locking (2PL)
Growing phase → acquire locks

Shrinking phase → release locks

Locks:

Shared (S) → read

Exclusive (X) → write

class LockManager {
public:
    void acquireShared(int txn_id, int page_id);
    void acquireExclusive(int txn_id, int page_id);
    void releaseLocks(int txn_id);
};
Pros:

Simple

Cons:

Deadlocks

⚡ Option 2: MVCC (Recommended)
Used by:

PostgreSQL

Oracle Database

Instead of locking:

Each row has:

struct MVCCHeader {
    uint32_t created_txn;
    uint32_t deleted_txn;
};
Reader sees:

Rows where created_txn <= current_txn

deleted_txn is NULL

Pros:

No read blocking

High concurrency

Cons:

More complex

Needs vacuum/garbage collection

We build basic synchronous TCP server.

📁 tcp_server.cpp
#include <iostream>
#include <cstring>
#include <unistd.h>
#include <arpa/inet.h>

#define PORT 54321
#define BUFFER_SIZE 4096

void handle_client(int client_socket);

int main() {
    int server_fd, client_socket;
    struct sockaddr_in address;
    int addrlen = sizeof(address);

    server_fd = socket(AF_INET, SOCK_STREAM, 0);

    address.sin_family = AF_INET;
    address.sin_addr.s_addr = INADDR_ANY;
    address.sin_port = htons(PORT);

    bind(server_fd, (struct sockaddr*)&address, sizeof(address));
    listen(server_fd, 5);

    std::cout << "DB Engine listening on port " << PORT << std::endl;

    while (true) {
        client_socket = accept(server_fd, 
                                (struct sockaddr*)&address, 
                                (socklen_t*)&addrlen);
        handle_client(client_socket);
    }

    return 0;
}
🔹 Client Handler
void handle_client(int client_socket) {
    char buffer[BUFFER_SIZE] = {0};

    while (true) {
        int bytes = read(client_socket, buffer, BUFFER_SIZE);
        if (bytes <= 0) break;

        char messageType = buffer[0];

        switch (messageType) {
            case 'Q':
                std::cout << "Query received\n";
                // Parse and execute
                send(client_socket, "Z", 1, 0);
                break;

            case 'B':
                std::cout << "Begin transaction\n";
                break;

            case 'C':
                std::cout << "Commit\n";
                break;

            default:
                std::cout << "Unknown message\n";

🔢 Cost Model Basics
Define cost unit as:

1 disk page read = 1 cost unit

🔹 Table Scan Cost
If table has:

1000 pages

Cost = 1000

🔹 Index Scan Cost (B+ Tree)
B+ tree height = 3
Leaf pages scanned = 10

Cost = 3 (tree traversal) + 10 = 13

Huge improvement.

🔹 Join Cost Formulas
Nested Loop Join
Cost = OuterPages + (OuterRows × InnerPages)
Very expensive.

Hash Join
Cost = BuildTablePages + ProbeTablePages
Usually faster.

4️⃣ Deadlock Detection Algorithm
Occurs in lock-based concurrency.

Example:

Transaction A locks page 1
Transaction B locks page 2

A waits for page 2
B waits for page 1

Deadlock.

🔹 Wait-For Graph
Construct graph:

Txn1 → Txn2
Txn2 → Txn1
Cycle = Deadlock.

🔹 Data Structure
std::unordered_map<int, std::vector<int>> waitForGraph;
🔹 Detection Algorithm (DFS)
bool hasCycle(int txn, std::set<int>& visited) {
    if (visited.count(txn)) return true;
    visited.insert(txn);

    for (auto neighbor : waitForGraph[txn]) {
        if (hasCycle(neighbor, visited))
            return true;
    }

    visited.erase(txn);
    return false;
}
Run periodically.

🔹 Resolution Strategy
Choose victim:

Youngest transaction

Least work done

Lowest priority

Abort victim.

🔥 Alternative: Avoid Deadlock
If using MVCC + minimal locks → very rare deadlocks.

PART 1 — Adding Sharding to Your Engine
1️⃣ What is Sharding?
Sharding = horizontal partitioning of data across multiple nodes.

Instead of:

Node1 → All data
We do:

Node1 → Users 1–1M
Node2 → Users 1M–2M
Node3 → Users 2M–3M
Each node runs your full DB engine.
